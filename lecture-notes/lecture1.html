Jevons' paradox in AI

Building gets cheaper→ Many more people build→ Advantage = picking an impactful problem + the right tools

Jevons' original observation: more efficient coal engines led to more coal use, not less. Cheaper building leads to more building, so building alone stops being a differentiator.

Why learn frameworks if a coding agent can build it?

Claude Code or Codex can write a customer-support agent and its infrastructure. You still have to understand, debug and maintain it. Agent design practice is young (databases and web dev have decades of it), so frameworks cut the boilerplate and let you spend time on the abstractions.

The app needsWhat it meansWhat the framework gives you
OrchestrationConnect models and tools, pass data between them, control what runs nextComponents, model/tool integrations, workflow routing
StateSave messages, draft replies and progress so the agent can continue laterLangGraph's saved state and pause/resume
ObservabilityInspect prompts, responses, tool calls and errors across a runRun inspection + tracing tools such as Arize

Course frameworks: LangGraph (Python) or LangFlow (visual, low-code), chosen for building, tracing and evaluating. The skills that matter: choosing workflows vs single agents vs multi-agent systems, writing evals for real tasks and failure cases, and debugging RAG failures (retrieval, context or generation).

Part 2 · Why AI needs different system design · Problem 1 of 3

Non-determinism

An LLM assigns a probability to every possible next token, samples one, appends it, and repeats. Sampling means the same prompt can produce different responses.

Sample the next token

Try it
The dog is …→LLM→ next-token probabilities

Probabilities from the lecture slide. Temperature isn't on the slides; it's the standard knob that sharpens (low) or flattens (high) this distribution. At 0 the model always picks the top token.

Taming it: iterative system design

Build, observe behaviour, improve, rebuild. Keep iterating until the experience is reliably good.

1BUILDNew features or fixes in small increments
2DEPLOYRelease the update to a subset of users
4IMPROVEFind weaknesses and opportunities
3OBSERVEGather eval results + customer signals

Behavior calibration (Observe + Improve) is where most of your time goes: did users behave differently than expected? Did the AI respond in a way that's calibrated to your product's expectations?

Example · coding agent · what you observeWrong edits, missed context, inconsistent style, flaky test fixes
What you changePatch the workflow, update prompts and tools, improve the evals

From user-driven to intent-driven

Agency is the authority to take actions toward a goal. Agency = decisions delegated to AI. Control = decisions retained by the person. Choose the balance for each part of the system.

Reasoning effort

Slide the lever

Reasoning is now standard in leading general-purpose models: task + context → internal reasoning (work through steps, consider alternatives, check an approach) → response. You'll see it as a "thinking" or "reasoning effort" setting.

Same input
Response
Help on hard tasks
Time to answer
Cost per task

Illustrative. The same model spends more computation (reasoning tokens) working through the task: it can improve difficult answers but usually adds time and cost.

Lens · avoid model-selection hell

Start with a mid-tier model and low reasoning effort, then adjust based on failures in your own tests.

Two levers: more reasoning, or a different model?

Reasoning as a leverGive the same person more time to work through it.More computation while answering; the learned model stays the same.Use when it understands the pieces but struggles to connect the steps: policy exceptions, multi-step math, planning with constraints.
A different model as a leverGive the problem to someone with different skills.Different learned capabilities; size and training both matter.Use when it needs different language, visual or domain capabilities: robotic writing, misread drawings, missed domain concepts.

Keep the task, data and instructions fixed. Compare quality, latency and cost on the same examples.

Part 5 · From context design to context engineering

Context engineering & prompting

You have the data and a model. How do they work together? Context engineering is the iterative plumbing that connects the model to what it needs.

Context engineering = Instructions + Tools + External / past knowledge
What it should doInstructionsRoute the ticket. Follow the routing rules.
What it can useToolsApproved tools to retrieve the information it needs.
What it should knowKnowledgeRelevant policy, order details and customer history.

Each gets engineered more deeply later in the course. This lecture zooms into instructions: prompting is how we give instructions to AI systems.

System prompt vs user prompt

System prompt · builder-providedRoute tickets to Invoices, Payments, Login issues or Security review. Return the queue and a brief reason. Do not change accounts.
User prompt · customer-providedPlease send me a copy of my invoice.
↓ both go to the AI model ↓
Invoices · The customer requests an invoice.

How prompting has evolved

2022 onward
Skill-based promptingPeople write instructions and examples to guide the router.
L1 · In-context learningL2 · Advanced methods
2023 onward
Automated prompt optimizationA model or algorithm proposes prompt changes; tests show which route better.
L3 · Meta-promptingL4 · Algorithmic optimization
Late 2024 onward
Self-optimizing modelsModels trained to reason through the task need less explicit reasoning guidance.
L0 · Reasoning models

These overlap; all three remain useful. Meta-prompting was demoed live in Arize.

Prompting a support router: then vs now

Earlier chain-of-thought promptRoute this ticket using the rules.
Think step by step: identify the issue, compare the categories, then decide.
Return the queue and a brief justification.
Prompting a reasoning modelRoute this ticket using the rules.
Return the queue and a brief justification.

Same output for both: Invoices · The customer requests an invoice. Reasoning models often need less instruction about how to reason.

Prompting today: only three things to focus on

  1. Define the task, context and expected output.
  2. Give examples if needed.
  3. Follow your model's prompting guide (OpenAI, Anthropic).
